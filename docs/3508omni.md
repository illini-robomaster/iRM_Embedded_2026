# DJI-compatible DM3519 chassis (3508omni)

This branch changes the MC02 `eoh_infant` target (`vehicles/Omni/eoh_mc02.cc`).
Other vehicle/example targets retain their existing motor drivers.

The original working software is preserved on `rickxu2/omni` at `d1c785a8`.
This branch requires DJI-compatible motor-controller firmware; changing the
MC02 program alone does not convert the motor controllers from DM VEL mode.

## CAN mapping

Viewed from above, IDs run clockwise: front right 1, back right 2,
back left 3, front left 4. Array indices retain the original kinematic order.

| Wheel | Old feedback / command | New feedback | New command slot |
|---|---|---|---|
| Front right M0 | 0x10 / 0x11 | 0x201 | 0x200 bytes 0..1 |
| Back left M1 | 0x12 / 0x13 | 0x203 | 0x200 bytes 4..5 |
| Back right M2 | 0x18 / 0x19 | 0x202 | 0x200 bytes 2..3 |
| Front left M3 | 0x16 / 0x17 | 0x204 | 0x200 bytes 6..7 |

Commands are signed big-endian current counts. Existing yaw, feeder and
flywheel commands continue to share 0x1FF with feedback IDs 0x205..0x208.
There must be no other sender commanding the 0x200 group.

## Control and configuration

The existing wheel kinematics still produce wheel-speed targets in rad/s.
Each wheel now has a host-side constrained PI speed loop feeding Motor3508
current commands. Initial gains are Kp=100, Ki=0.5 per iteration, Kd=0;
integral contribution is capped at 500 counts, output at +/-3000 counts.
These are provisional bench parameters, not validated DM3519 tuning.

Motor3508 decodes feedback velocity as RPM and converts it to rad/s.
`CHASSIS_FEEDBACK_TO_WHEEL_RATIO` defaults to 1.0, assuming firmware feedback
is wheel/output-shaft speed. Confirm the actual firmware's speed units,
shaft reference, reduction ratio, current-count scaling and direction before
hardware operation. Set the ratio to feedback-shaft speed / wheel-shaft speed;
do not assume the DJI M3508 gearbox ratio applies to DM3519.

No DM enable/disable commands or repeated startup enable sequence are sent
to chassis motors. Startup and remote disable send zero current. PMM power-off
zeros chassis current and resets PI state. PMM restoration resets PI state;
normal current control resumes only while all four feedback streams are fresh.
Any missing feedback or age over 100 ms zeros all four currents and resets PI.
Feedback freshness indicates communication, not proof the controller is healthy.

Feeder target 110 rad/s, referee 14/16-byte heat-packet compatibility, and the
existing 120 W measured-power velocity scaling are retained. The latter is
feedback limiting, not an instantaneous power guarantee, and depends on valid
power telemetry from the actual referee firmware.

## Validation

ARM GCC build of `eoh_infant.elf` passed. Hardware compatibility, current scaling,
direction, PI tuning, cold startup, PMM recovery and heat protection have not
been validated on this branch. No firmware was flashed during this change.

Build from the repository with the portable tool environment loaded:

```powershell
. '..\embedded-tools\env.ps1'
cmake --build build --target eoh_infant.elf --parallel 8
```
